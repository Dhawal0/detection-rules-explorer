Java HotSpot Fatal Error Log Created

Last updated 5 days ago on 2026-11-18
Created 5 days ago on 2026-11-18

About

Identifies the creation of a Java HotSpot fatal error log by a Java process. The JVM writes "hs_err_pid*.log" after a fatal error, such as an access violation, segmentation fault, or unrecoverable native-code failure. This may indicate an unsuccessful attempt to exploit a Java memory-corruption vulnerability. In particular, failed Java4Shell (CVE-2026-114938) heap-grooming or corruption attempts may crash the JVM before remote code execution succeeds. This event indicates a JVM crash and possible exploit attempt; it does not by itself establish successful exploitation or remote code execution.

False Positives
JVM defects, incompatible or vulnerable JNI libraries, Java agents, profilers, faulty native modules, hardware problems, and resource exhaustion can legitimately cause HotSpot to terminate and write a fatal error log.
