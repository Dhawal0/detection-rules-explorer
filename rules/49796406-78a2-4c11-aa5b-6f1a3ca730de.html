Microsoft Foundry Keys or Connection Secrets Accessed by New Principal

Last updated 16 days ago on 2026-10-23
Created 16 days ago on 2026-10-23

About

Identifies the first time in seven days that a high-privilege Azure principal lists or regenerates the API keys of a Microsoft Foundry (Azure AI Services) account, or reads the stored secrets of a Foundry account or project connection. Account keys grant direct inference access to every model deployment on the account and bypass Entra ID conditional access, and connection secrets hold credentials for downstream services such as Azure OpenAI, storage, and search. A compromised identity retrieving these keys is a common first step in LLMjacking and in pivoting from a Foundry project to the data it is connected to.

False Positives
Administrators with Owner or Contributor roles opening the Keys and Endpoint blade in the Azure portal or Foundry portal, which issues a listKeys call. Confirm the activity with the principal and prefer Entra ID authentication over key-based access. ; Infrastructure-as-code pipelines and deployment scripts that read keys to configure applications. Prefer managed identities, or add exceptions for the service principals that run these pipelines.
